# v0.5.0 计划

## 版本目标

`v0.5.0` 聚焦两件事：

1. 基于新设计稿把主界面从“功能可用”推进到“更像正式桌面工具”
2. 补齐一组高频设备快捷动作，减少用户频繁切到外部终端或手敲 adb 命令

这版 **不纳入** 旧 backlog 中的网络自动重连、设备分组筛选、多设备批量操作、连接诊断、实时 Logcat 工作台等大块能力，避免范围失控。

## 已确认产品决策

1. `v0.5.0` 范围只包含：
   - 主界面重构
   - 从列表页主动断开网络设备
   - 复制设备序列号
   - 从列表页直接打开设备 Shell
   - ADB Server 管理与恢复
   - 拖拽 APK 安装 / 普通文件传输
2. 打开设备 Shell：**优先 Windows Terminal，找不到时回退 PowerShell**
3. 主动断开：**仅网络设备支持**，USB 设备不显示或不启用断开动作
4. 拖拽目标设备：**优先当前选中设备**；未选中时弹出目标设备选择
5. 普通文件默认推送到：**`/sdcard/Download`**
6. 支持一次拖入多个文件：APK 逐个安装，普通文件逐个推送；混合拖入时按类型分别处理

## 代码现状判断

当前代码已经具备可复用基础：

- `src/app.rs`
  - 已有顶部摘要区、设备详情区、设备列表区、状态区、设置/连接/清理弹窗
  - 已具备设备选中、别名、置顶、连接设备、自动刷新等状态管理
- `src/adb.rs`
  - 已有 `list_devices`、`connect_device`、`spawn_logcat`
  - 适合继续扩展 `disconnect`、`kill-server/start-server`、`install`、`push`
- `src/fs_utils.rs`
  - 已有打开路径/URL 能力
  - 适合补“打开终端并执行命令”的 Windows 平台封装
- `src/models.rs`
  - `AppEvent` 目前覆盖设备刷新、连接、采集、清理，后续需要扩展为“断开 / 拖拽任务 / server 恢复”等异步结果
- `locales/zh-CN.json` / `locales/en.json`
  - 已是所有 UI 文案入口，需要继续保持双语同步

结论：**现有结构足够支撑 `v0.5.0`，但需要把 `src/app.rs` 的 UI 逻辑进一步拆成更清晰的区域/辅助函数，否则改版会越来越难维护。**

## 变更内容

### 1. 主界面重构

**需求**：
- 参考 `assets/ui_redesign_reference_20260430.png` 重构主界面
- 重点覆盖左侧导航、顶部统计卡片、当前设备详情区、设备列表区、底部状态/日志区
- 在不打断现有功能的前提下，提升信息层级、专业感和可扩展性

**方案**：
- 保留当前单窗口架构，不引入新页面路由系统
- 通过重新组织 `ui_summary / ui_selected_device / ui_devices / ui_status` 的布局来贴近设计稿
- 将工具栏入口、设备详情动作、列表动作统一成更稳定的视觉层级
- 为后续拖拽态提示、批量动作、日志工作台预留空间

**改动**：

#### `src/app.rs`
- 重组主界面布局和间距
- 视需要提取更明确的 UI 辅助函数（如侧边栏、工具区、设备动作区）
- 确保现有设置、连接、清理历史等弹窗仍可用

#### `locales/*.json`
- 补齐新布局涉及的标题、说明、动作文案

**风险点**：
- `app.rs` 当前承担较多状态和渲染逻辑，重构时要避免把事件处理和布局改动缠死
- 需要避免 UI 改版影响现有“选中设备 / 启停采集 / 打开日志”行为

### 2. 从列表页主动断开网络设备

**需求**：
- 在设备列表中对网络设备提供“断开”动作
- 执行后刷新设备状态并给出成功/失败反馈

**方案**：
- 仅对网络设备 serial（`host:port`）启用断开按钮
- 通过 `adb disconnect <target>` 执行断开
- 断开成功后触发设备列表刷新

**改动**：

#### `src/adb.rs`
- 新增 `disconnect_device`
- 新增网络设备 serial 判定辅助逻辑
- 补充输出解析和错误信息整理

#### `src/app.rs`
- 列表区和设备详情区增加断开动作
- 断开中禁用重复点击
- 处理异步事件和状态提示

**测试**：
- 解析 `adb disconnect` 成功 / 失败输出
- 网络设备 serial 判定逻辑

### 3. 复制设备序列号

**需求**：
- 支持从列表页或详情区一键复制设备序列号
- 方便直接去外部终端执行 `adb -s <serial> ...`

**方案**：
- 列表页提供轻量复制入口
- 详情区保留更明显的复制按钮
- 成功复制后给出明确提示

**改动**：

#### `src/app.rs`
- 新增复制动作和反馈提示
- 保证复制的是原始 serial，而不是别名

**测试**：
- 将复制逻辑尽量下沉为可验证辅助函数；UI 层重点做编译与行为验证

### 4. 从列表页直接打开设备 Shell

**需求**：
- 对指定设备一键打开系统终端并执行 `adb -s <serial> shell`

**方案**：
- Windows 平台优先尝试 `wt.exe`
- 若系统没有 Windows Terminal，则回退到 PowerShell
- 统一由平台封装函数负责命令拼装与进程拉起

**改动**：

#### `src/fs_utils.rs`
- 新增 Windows 终端拉起封装
- 对外暴露“用 adb + serial 打开 shell”的能力

#### `src/app.rs`
- 列表区和详情区增加打开 Shell 动作
- 失败时展示明确错误

**测试**：
- 为命令拼装辅助逻辑补单元测试
- 至少覆盖 Windows Terminal / PowerShell 两种分支的参数生成

### 5. ADB Server 管理与恢复

**需求**：
- 提供图形入口重启 ADB Server，作为连接异常时的全局恢复手段
- 执行后刷新设备列表

**方案**：
- 提供统一的 “Restart ADB Server” 动作
- 内部按 `adb kill-server` + `adb start-server` 顺序执行
- 结束后刷新设备列表并反馈结果

**改动**：

#### `src/adb.rs`
- 新增 server 管理函数
- 统一输出解析

#### `src/app.rs`
- 在工具栏或设置中增加恢复入口
- 处理执行中状态，避免重复触发

**测试**：
- `kill/start` 输出与异常组合的解析
- 执行失败时的错误文本是否可读

### 6. 拖拽 APK 安装 / 普通文件传输

**需求**：
- 支持把 APK 直接拖进窗口安装到设备
- 支持把普通文件拖进窗口推送到 `/sdcard/Download`
- 支持多文件与混合拖入

**方案**：
- 监听 `egui` 的拖入文件事件
- 将拖入文件按 APK / 普通文件分类
- 目标设备优先使用当前选中设备；若没有选中设备，则弹出目标设备选择
- 后台线程串行执行安装 / 推送，避免 UI 阻塞

**改动**：

#### `src/adb.rs`
- 新增 `install_apk`、`push_file`
- 统一处理命令输出和错误

#### `src/models.rs`
- 扩展拖拽任务 / 任务完成相关事件

#### `src/app.rs`
- 增加拖拽文件检测、文件分类、目标设备选择、任务调度与结果提示
- 在 UI 中增加轻量拖拽提示或目标确认弹窗

**测试**：
- 文件分类辅助函数
- APK / 普通文件命令参数生成
- 多文件输入的任务拆分逻辑

## 推荐实施顺序

1. **先做 UI 重构骨架**
   - 把主界面布局调整到位
   - 给设备详情区和列表动作留出稳定位置
2. **再补轻量快捷动作**
   - 复制序列号
   - 打开设备 Shell
   - 断开网络设备
3. **再做 ADB Server 恢复入口**
   - 这块逻辑独立，便于补纯命令层测试
4. **最后做拖拽安装 / 传输**
   - 这是这版里交互和异步状态最复杂的一块
   - 放在前面动作稳定后再接入更稳
5. **统一收口**
   - README / CHANGELOG 双语同步
   - `cargo fmt` / `cargo test` / `cargo check`
   - Windows EXE/zip 构建验证
