# 无线调试与指定 IP 查找

## 连接设备

“连接设备”包含三个入口：

- **无线调试**：定期查询 ADB 的 mDNS 服务。手机开启“无线调试 → 使用配对码配对设备”后，选择配对服务，输入六位配对码。配对成功后重新查询连接服务；同一 IP 只有一个无线连接服务时自动连接。多个服务时由用户选择。
- **IP 查找**：输入一个设备 IP，查询该 IP 的 mDNS 服务并扫描 TCP 端口。快速查找优先历史端口，再检查 5555 和 30000–65535；完整扫描覆盖 1–65535。结果出现后即可连接，也可以停止扫描。
- **手动连接**：输入主机名、IPv4 或 `[IPv6]:端口`。普通 TCP/IP 调试可省略端口，默认 5555；勾选“无线调试地址”时必须填写实际端口。

配对服务和连接服务使用不同端口。端口扫描识别连接服务，不会把普通开放端口当成配对服务。mDNS 不可用时可手动填写配对地址；配对后若仍无法发现连接服务，会按该 IP 快速扫描，亦可手动输入连接地址。

地址及配对码支持全角数字、全角 ASCII、中文句号和冒号的规范化。输入法组合文本尚未确认时不改写；确认候选的回车不会提交连接。

成功连接后保存规范化地址。无线调试历史记录会重新发现当前端口；同一 IP 的传统 TCP/IP 连接单独记忆，仍使用原端口。不会保存配对码。

## 扫描行为

- 仅扫描输入的单个 IP；不扩展为整个网段，也不要求先 ping 成功。
- 单个工作线程使用异步 Socket，最多 256 个并发探测。快速查找连接超时 220 ms，完整扫描 450 ms，ADB 握手另限 650 ms。
- 快速查找总时限 45 秒，完整扫描总时限 180 秒。超时、扫描中止和正常完成分别显示，超时端口不视为已确认关闭。
- 仅接收符合 ADB 数据包格式的握手响应：传统 `AUTH` / `CNXN` 或无线调试 `STLS`。不执行设备 shell 指令，不自动尝试配对码。
- 关闭弹窗和退出程序会取消发现、配对与扫描；过期任务结果不会用于新弹窗。单次 ADB 连接也有 12 秒时限。
- mDNS 查询、配对分别限制为 5 秒、20 秒。配对码通过子进程标准输入传递，不放入命令行参数或日志。

## 本地验证

```powershell
cargo test
cargo clippy --all-targets -- -D warnings
cargo build --release
pwsh -File scripts/e2e_windows.ps1 -Python C:\path\to\python.exe
```

Python 需要 3.x。原生 E2E 使用 Windows UI Automation 操作真实 Release 程序，通过独立便携配置、模拟 ADB 子进程和仅监听 `127.0.0.1` 的 TCP 服务验证完整流程。脚本会暂时显示测试窗口，结束后关闭自己启动的进程，不读取或修改正式安装的配置。结果、日志及截图保存在 `target/e2e/<时间>/`。

远程或锁定的 Windows 桌面可能无法通过 GDI 捕获 OpenGL 内容。视觉验证可使用 `cargo build --release --features e2e`，再给脚本添加 `-RendererCapture`，由真实渲染器输出截图。这个测试功能不会注入业务输入或模拟应用状态；交付制品使用普通 `cargo build --release`，不包含截图控制入口。普通制品在截图不可用的环境可添加 `-SkipScreenshots` 跑功能 E2E。仅复验界面变更时可用 `-SkipFullScan` 跳过已通过且实现未变的全端口扫描。

Rust 测试及原生 E2E 都会现场编译模拟 ADB，要求 PATH 中可找到支持 edition 2024 的 `rustc`，并具备当前平台的链接工具链；这与项目自身的 edition 要求一致。Rust 测试在每个测试进程内只编译一次并复用，各测试仍使用独立配置目录。

Rust 测试额外覆盖输入法事件、非法输入、ADB 数据包识别、配对码标准输入、动态端口、扫描取消、进程超时、多个连接服务及过期回调。

这些测试不能替代不同 Android 厂商设备、真实局域网组播和实际输入法的试用。短超时可能漏掉弱网络下的设备，应使用完整扫描重试或手动填写端口。

当前为下一功能版本的本地预览开发，包版本暂保持 `0.7.0`；正式 `0.8.0` 版本号、提交整理和远端发布等待试用确认。
